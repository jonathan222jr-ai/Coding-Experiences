▸ AGENT: FULLSTACK  (6765ms)
  Task: what's the difference between var, let, const

  ANSWER: `var` is function-scoped and hoisted, which causes weird bugs where variables exist before you declare them. `let` and `const` are block-scoped, which is way more predictable. `const` just means you can't reassign the binding — but if it's an object or array, you can still mutate the contents.
  
  CODE:
  ```typescript
  var x = 1; // hoisted, function-scoped, can reassign
  let y = 2; // block-scoped, can reassign
  const z = { count: 0 }; // block-scoped, can't reassign z
  z.count = 5; // but this is totally fine
  
  if (true) {
    var leaked = "I exist outside this block"; // 😬
    let safe = "I stay in here";
  }
  console.log(leaked); // works, probably not what you wanted
  console.log(safe);   // ReferenceError
  ```
  
  TRADEOFF: I basically never use `var` anymore — `const` by default, `let` when I know I need to reassign. Some people argue `const` gives a false sense of immutability since objects are still mutable, so for deep immutability you'd need something like `Object.freeze()` or a library like Immer.
