▸ AGENT: FULLSTACK  (5355ms)
  Task: running three promises sequentialy with await versus concurrently with promise.a

  ANSWER: Sequential await runs each promise one after another — the second waits for the first to finish. Promise.all fires them all at once and waits for all to resolve, which is way faster when the operations are independent (like fetching user data, posts, and comments at the same time).
  
  CODE:
  ```typescript
  // Sequential - slow, ~3 seconds total
  const user = await fetchUser(id);
  const posts = await fetchPosts(id);
  const comments = await fetchComments(id);
  
  // Concurrent - fast, ~1 second total
  const [user, posts, comments] = await Promise.all([
    fetchUser(id),
    fetchPosts(id),
    fetchComments(id),
  ]);
  ```
  
  TRADEOFF: Promise.all is all-or-nothing — if one promise rejects, the whole thing fails even if the others succeed. In that case I'd use `Promise.allSettled` to get results from all of them regardless, then handle failures individually. Sequential makes sense when operations actually depend on each other, like when you need the user ID from the first call to make the second call.
