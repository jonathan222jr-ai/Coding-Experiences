  Task: handle loading/ error states to avoid setting state after an unmoubnt

  ANSWER: The cleanest modern approach is using an AbortController to cancel fetch requests when the component unmounts. In the cleanup function of your useEffect, you call `abort()` which causes the fetch to reject, and you just ignore that specific error. This prevents any state updates from firing after the component is gone.
  
  ```typescript
  useEffect(() => {
    const controller = new AbortController();
    
    const fetchData = async () => {
      setLoading(true);
      try {
        const res = await fetch('/api/data', { signal: controller.signal });
        const data = await res.json();
        setData(data);
      } catch (err) {
        if ((err as Error).name !== 'AbortError') {
          setError('Something went wrong');
        }
      } finally {
        setLoading(false);
      }
    };
  
    fetchData();
    return () => controller.abort();
  }, []);
  ```
  
  TRADEOFF: The old `isMounted` flag pattern also works but it's more boilerplate and doesn't actually cancel the network request — it just skips the state update. AbortController is better because it cancels the request entirely, saving bandwidth. If you're using React Query, it handles all of this for you automatically.
